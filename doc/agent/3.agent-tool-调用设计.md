# Agent 工具调用设计

本文档描述了 OpenClaw 中 Agent 工具调用系统的整体架构设计。

## 概述

OpenClaw 的工具调用系统是一个分层、可扩展的设计，支持核心工具、插件工具、权限控制、钩子拦截和事件流。系统基于 `@mariozechner/pi-agent-core` 构建，并在此基础上增加了多层扩展。

## 核心组件

### 1. 工具定义层 (Tool Definition)

每个工具必须符合 `AnyAgentTool` 接口 (`src/agents/tools/common.ts`):

```typescript
type AnyAgentTool = AgentTool<any, unknown> & {
  ownerOnly?: boolean;  // 仅所有者可用
};
```

标准工具返回格式:

```typescript
// 必须符合 AgentToolResult 格式
{
  content: ContentBlock[],       // 内容块数组 (text / image)
  details: unknown,               // 结构化详情 (用于机器处理)
}
```

帮助函数:

```typescript
// 创建 JSON 格式结果
jsonResult(payload): AgentToolResult

// 仅所有者工具包装
wrapOwnerOnlyToolExecution(tool, senderIsOwner): AnyAgentTool

// 创建图片结果
imageResult({ label, path, base64, mimeType }): Promise<AgentToolResult>
```

### 2. 工具注册

**核心工具** 在 `src/agents/openclaw-tools.ts` 中集中创建:

```typescript
export function createOpenClawTools(options): AnyAgentTool[] {
  // 1. 创建所有核心工具 (browser, canvas, cron, message, tts, gateway 等)
  // 2. 加载插件工具 resolvePluginTools()
  // 3. 合并返回
  return [...tools, ...pluginTools];
}
```

**插件工具** 通过插件系统注册 (`src/plugins/tools.ts`):

```typescript
// 插件调用 api.registerTool() 注册
api.registerTool({
  name: "my_tool",
  description: "Do a thing",
  parameters: Type.Object({ ... }),
  async execute(_id, params) {
    return { content: [...] };
  },
}, { optional: true }); // 可选工具需要用户显式允许
```

插件工具支持可选模式，只有在用户显式添加到 allowlist 后才会启用。支持三种匹配方式:

- 具体工具名 `"tool_name"`
- 插件 id `"plugin_id"` (启用该插件所有工具)
- 分组 `"group:plugins"` (启用所有插件工具)

### 3. 权限策略系统

权限策略采用多层合并策略 (`src/agents/pi-tools.policy.ts`):

1. **全局策略** `config.tools`
2. **全局按提供者策略** `config.tools.byProvider[provider]`
3. **Agent 级别策略** `config.agents.list[].tools`
4. **Agent 按提供者策略** `config.agents.list[].tools.byProvider[provider]`
5. **profile 基策略** + `alsoAllow` 增量添加

子agent 有额外的系统级拒绝列表 (`src/agents/pi-tools.policy.ts:24-48`):

```typescript
// 始终禁止
const SUBAGENT_TOOL_DENY_ALWAYS = [
  "gateway", "agents_list", "whatsapp_login", "session_status",
  "cron", "memory_search", "memory_get", "sessions_send",
];

// 叶子节点禁止 (depth >= maxSpawnDepth)
const SUBAGENT_TOOL_DENY_LEAF = [
  "subagents", "sessions_list", "sessions_history", "sessions_spawn",
];
```

策略匹配逻辑 (`src/agents/tool-policy-match.ts`):

- 如果 `allow` 非空，工具必须在 allow 列表中才允许
- 如果 `deny` 包含工具，拒绝
- 否则允许

### 4. 格式适配层

OpenClaw 工具定义需要适配为 pi-agent-core 的 `ToolDefinition` 格式 (`src/agents/pi-tool-definition-adapter.ts`):

主要职责:

1. **参数兼容**: 处理新旧两种 `execute` 参数顺序
   - 当前: `(toolCallId, params, AbortSignal, onUpdate)`
   - 旧版: `(toolCallId, params, onUpdate, ctx, AbortSignal)`
2. **Before 钩子**: 在执行实际工具前调用 `before_tool_call` 插件钩子
3. **结果标准化**: 将任意返回值转换为标准 `{content, details}` 格式
4. **错误处理**: 捕获异常并返回标准化错误 JSON

代码:

```typescript
export function toToolDefinitions(tools: AnyAgentTool[]): ToolDefinition[] {
  return tools.map(tool => ({
    name: tool.name,
    description: tool.description,
    parameters: tool.parameters,
    execute: async (...args) => {
      // 1. 解析参数
      const { toolCallId, params, onUpdate, signal } = splitToolExecuteArgs(args);

      // 2. 运行 before_tool_call 钩子
      const hookOutcome = await runBeforeToolCallHook(...);
      if (hookOutcome.blocked) throw new Error(hookOutcome.reason);

      // 3. 执行工具
      const rawResult = await tool.execute(toolCallId, hookOutcome.params, signal, onUpdate);

      // 4. 标准化结果
      return normalizeToolExecutionResult({ toolName, result: rawResult });
    }
  }));
}
```

**客户端工具** (由客户端执行的工具) 特殊处理:

```typescript
export function toClientToolDefinitions(
  tools: ClientToolDefinition[],
  onClientToolCall?: (toolName, params) => void,

  // 返回 "pending" 状态，通知客户端需要执行这个工具
  // 客户端执行完成后会带回结果
}
```

### 5. 钩子系统

#### before_tool_call

在工具执行**之前**调用，可以:

- 拦截并阻止工具调用 (`blocked: true`)
- 修改工具参数 (`params`)

使用场景: 循环检测、权限检查、参数注入

```typescript
// src/agents/pi-tools.before-tool-call.ts
export async function runBeforeToolCallHook({
  toolName, params, toolCallId, ctx,
}): Promise<HookOutcome>
```

循环检测 (`src/agents/pi-tools.before-tool-call.runtime.ts`):

- 跟踪工具调用历史
- 检测重复调用模式 (same tool + similar params)
- 严重循环直接阻止调用

#### after_tool_call

在工具执行**之后**调用，可以:

- 观察结果/错误
- 记录日志
- 触发副作用

事件结构 (`src/plugins/types.ts`):

```typescript
{
  toolName, params, runId, toolCallId, result, error, durationMs,
  agentId, sessionKey, sessionId,
}
```

### 6. 事件流处理

工具执行过程中会发出三个阶段的事件 (`src/agents/pi-embedded-subscribe.handlers.tools.ts`):

1. **tool start**: 工具开始执行
   - 记录开始时间和参数
   - 发送 `stream: "tool"` 事件 `{ phase: "start" }`
   - 发出工具摘要 (UI 展示)

2. **tool update**: 增量更新 (支持流式输出)
   - 转发 `partialResult`
   - 发送 `{ phase: "update" }`

3. **tool end**: 工具执行完成
   - 消毒结果 (截断文本、移除图片数据)
   - 提取错误信息
   - 跟踪 messaging 工具发送 (用于去重)
   - 运行 `after_tool_call` 钩子
   - 发送 `{ phase: "result" }`
   - 对特殊结果 (如 exec 等待审批) 发出额外回调

### 7. 结果消毒

结果返回给 LLM 之前会进行消毒处理 (`src/agents/pi-embedded-subscribe.tools.ts`):

**文本截断**:

- 工具结果默认最大 `8000` 字符
- 错误信息最大 `400` 字符
- 超出截断并添加 `…(truncated)…`

**图片处理**:

- 从结果中移除 base64 数据 (避免日志过大)
- 保留 `bytes` 长度信息和 `omitted: true` 标记
- 图片路径通过 `MEDIA:` 特殊标记提取

**媒体信任**:

只有核心白名单中的工具可以输出本地 `MEDIA:` 路径:

```typescript
const TRUSTED_TOOL_RESULT_MEDIA = new Set([
  "read", "write", "edit", "exec", "image", "browser", /* ... */
]);
```

插件工具只允许输出 HTTP URLs 防止任意文件访问。

**错误提取**:

按优先级从结果中提取错误信息:

1. `details.error` / `details.message`
2. `error` / `message` 根字段
3. `details.status` 是 error/timeout -> 提取
4. 从文本内容尝试 JSON 解析

## 配置格式

```typescript
{
  tools: {
    // 基础允许列表
    allow?: string[],
    alsoAllow?: string[],  // 在 profile 基础上添加
    deny?: string[],

    // 按模型提供者配置
    byProvider?: {
      "openai": { allow, alsoAllow, deny },
      "anthropic/claude-3-5-sonnet": { allow, alsoAllow, deny },
    },

    // 工具 profile (预设列表)
    profile?: string,

    // 子agent 工具策略
    subagents: {
      tools: { allow, alsoAllow, deny },
    },

    // 循环检测配置
    loopDetection?: {
      enabled?: boolean,
      maxRepeats?: number,        // 最大重复次数
      similarityThreshold?: number, // 参数相似度阈值 (0-1)
    };
  },

  agents: {
    list: [{
      id: "my-agent",
      tools: {
        // 同全局 tools 配置，会合并到全局
        allow?: string[],
        // ...
      },
    }],
  },
}
```

## Allowlist 匹配语法

| 格式 | 匹配 |
|------|------|
| `tool_name` | 精确匹配工具名 |
| `plugin_id` | 匹配插件下所有工具 |
| `group:plugins` | 匹配所有插件工具 |

## 核心工具分类

OpenClaw 包含以下几类核心工具:

| 类别 | 工具 |
|------|------|
| 文件系统 | `read`, `write`, `edit`, `glob`, `grep` |
| 命令执行 | `exec`, `process` |
| 浏览/检索 | `browser`, `web_fetch`, `web_search` |
| 多代理 | `sessions_spawn`, `sessions_send`, `sessions_yield`, `sessions_list`, `sessions_history`, `subagents` |
| 媒体处理 | `image`, `pdf`, `canvas`, `tts` |
| 消息发送 | `message` |
| 系统 | `gateway`, `cron`, `session_status`, `agents_list` |
| 节点 | `nodes` |

## 扩展点

1. **插件工具**: 通过 `api.registerTool()` 注册自定义工具
2. **before_tool_call 钩子**: 插件可以拦截所有工具调用
3. **after_tool_call 钩子**: 插件可以观察工具执行结果
4. **客户端工具**: 支持将工具执行委托给客户端 (如 UI 端)
5. **分组策略**: 渠道插件可以实现 `groups.resolveToolPolicy` 为特定群组配置不同工具权限

## 安全考虑

1. **权限分层**: 全局 -> Agent -> 子agent 逐层过滤
2. **所有者限制**: 敏感工具可标记 `ownerOnly` 仅所有者可用
3. **媒体信任**: 仅信任核心工具输出本地路径
4. **结果大小限制**: 防止超大结果炸上下文窗口
5. **循环检测**: 防止 LLM 陷入无限工具调用循环
6. **子agent 深度限制**: 系统级禁止危险工具给子agent
